# Tactical Crow v0.3：更专业、更广泛、更准确的资源检索

> 日期：2026-10-12
> 基线：v0.2（`2026-10-12-crow-v0.2-changes.md`）
> 用户确认的范围：免费 key 学术 API + arXiv；中文文献通过本地文献库导入；默认启用 LLM 摘要筛选；建立检索评测集（金标为草稿，待人工审阅）

## 1. 一次运行的完整流程

```text
需求 ─┬─ 术语词表匹配 → 规划器提示词中的术语表
      └─ LLM 规划：研究问题 + 6 类检索式（网页 / 学术 / 条令 / 技术报告 / 中文 / 关键词）
             └─ 词表确定性扩展：现行条令版本、学术术语组合、中文检索串

第 1 轮 发现：Tavily 网页 · Tavily 条令域名 · Tavily 技术报告域名 ·
              OpenAlex · Semantic Scholar · arXiv · CORE · 本地文献库
        初筛：URL / DOI / 规范化标题去重 → DOI 核验（OpenAlex，免费）→ 撤稿拒绝 →
              条令替代标记 → 屏蔽站点与无全文拒绝 → 来源质量 A–D
        摘要筛选：LLM 按研究问题给出 0–3 分；0 分剔除，分数参与排序
        下载：按优先级采集，PDF/HTML 依据响应内容判定，内容哈希合并镜像
        引文扩展：从最优学术来源出发，各取参考文献和施引文献，走同样流程
  → PaperQA 建库（一次）→ 逐题回答 → Falcon 门槛

第 2 轮（仅当有问题证据不足时）：规划器针对薄弱问题换角度出检索式 →
        采集（与第 1 轮全局去重）→ 增量加入同一语料库 → 只重答薄弱问题
```

## 2. 三个目标分别如何落实

**更专业**
- `domain/data/tactical_vocabulary.toml`：26 个战术概念，覆盖队形、运动方式、分队类型、有人/无人协同、任务分配、威胁评估与火力分配（TEWA）、地形、行为树/状态机、计算机生成兵力（CGF）和 AFSIM，每个概念含中英同义词、学术术语和对应条令。规划器提示词中注入命中的术语，并做确定性扩展。
- `domain/data/doctrine_supersession.toml`：条令替代关系表。已核实的条目：FM 3-20.15 → ATP 3-20.15（2025 年修订版），FM 7-92、FM 3-21.94 → ATP 3-20.98；其余标为 `verified = false`。旧版编号会自动改搜新版，旧版来源在质量评分中扣 0.15 分并在报告中提示。
- 条令编号识别支持 Army 文件名写法（`ATP_3-20.15-000-WEB-1.pdf`）和 URL 编码写法。
- 新增技术报告渠道：DTIC、NPS Calhoun、AFIT、RAND、CNA、MITRE、NASA NTRS、NATO STO、FOI。DTIC 没有公开 API，因此通过 Tavily 定向检索这些域名。

**更广泛**
- 新数据源：Semantic Scholar（覆盖 CS/AI/机器人方向好，提供引文图）、arXiv、CORE（开放获取全文、学位论文）；OpenAlex 新增引文图查询和 DOI 查询。
- 引文扩展：默认从 3 篇种子文献出发，每个方向各取 10 篇；有 S2 key 时使用 Semantic Scholar，否则使用 OpenAlex（过滤类查询，费用低）。
- 证据不足补检：默认追加 1 轮，额外最多 6 个来源。
- 中文文献：报告给出中文检索串和知网/万方直达链接；下载的全文放入 `data/library/` 后，下次运行会自动筛选纳入（可附 `.meta.toml` 元数据）。附有元数据的期刊论文一般评为 B 级。

**更准确**
- LLM 摘要筛选（`literature/screening.py`，提示词版本 `crow-screening-2026.10.1`）：每 8 个候选为一批，并发 4，评分规则写在提示词中。筛选失败的候选按中性分处理，不会因此丢失。
- DOI 核验：标题不一致时剥离 DOI，避免产生错误引用；撤稿论文直接拒绝；补全缺失的作者、年份、载体、被引数。
- 排序公式：`0.45 × 来源质量 + 0.40 × 筛选分/3 + 0.15 × 提供方排名`。

## 3. 检索评测

- 金标：`eval/retrieval_gold.toml`，共 12 个需求、22 个应找到的来源。DOI 均已通过 Crossref 核对；条令类有 4 条尚待核实。**状态为 draft，请审阅后改为 reviewed。**
- 指标：发现召回率 → 筛选后保留召回率 → 采用召回率，分别统计全部金标和 must 金标；标注 `precision_labels.csv` 后可计算采用精确率。
- 命令：

```bash
python -m afsim_research_agent.evaluation.retrieval verify
python -m afsim_research_agent.evaluation.retrieval run                # 或 --cases armor-terrain-formations,tewa
python -m afsim_research_agent.evaluation.retrieval rescore --run-dir data/eval/<run> --labels data/eval/<run>/precision_labels.csv
```

建议先跑一次作为 v0.3 基线，之后每次调整检索策略、词表或评分规则，都与基线的 `evaluation.json` 对比。

## 4. 需要注册的免费 key

| 变量 | 作用 | 不配置时的影响 |
| --- | --- | --- |
| `OPENALEX_API_KEY` | OpenAlex 按用量计费：无 key 每天约 0.1 美元额度，有 key 每天 1 美元（约 1000 次搜索） | 很快耗尽额度，学术检索返回 `search_failed` |
| `SEMANTIC_SCHOLAR_API_KEY` | 独享每秒 1 次的速率 | 共享池经常返回 429；客户端会降速并重试 |
| `CORE_API_KEY` | 开放获取全文聚合 | 跳过 CORE 渠道 |
| `CROW_CONTACT_EMAIL` | 用于 User-Agent 和 OpenAlex 的 mailto 参数 | 部分站点会拒绝访问 |

## 5. 成本与耗时估算（默认参数，单次运行）

- 学术检索：OpenAlex 搜索约 5 次；S2、arXiv 各约 5 次（S2 无 key 时每 3 秒 1 次，arXiv 固定每 3 秒 1 次）；引文扩展约 6 次过滤查询。
- LLM：规划 1 次，补检规划 0–1 次，筛选约 5–10 次短调用（不超过 80 个候选）。
- 预计比 v0.2 多 1–3 分钟，主要花在 arXiv/S2 的限速等待上。

## 6. 验证状态

- 开发容器中有 197 个单元测试和 `ruff check` 通过；PaperQA2、Tavily、trafilatura 使用替身。
- 需要在 Mac 上确认的事项：
  - Semantic Scholar、arXiv、CORE 的真实返回格式，可用 `pytest -m live` 检查；
  - 知网、万方链接格式在你的网络环境下能否打开；
  - LangChain `with_structured_output(...).batch(return_exceptions=True)` 在 DashScope 上的表现。

## 7. 下一步建议

1. 审阅金标集，补充你认为必须找到的文献，尤其是中文文献，然后跑出 v0.3 基线。
2. 根据评测结果调整：`CROW_SCREEN_MIN_SCORE`（1 或 2）、排序权重、词表条目。
3. 主张级证据合并与冲突检测仍未实现，应与 Falcon 的 `TacticalBehaviorSpec` 一起设计。
