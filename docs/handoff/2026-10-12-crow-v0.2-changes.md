# Tactical Crow v0.2 变更说明：可诊断采集、学术与条令检索、来源质量和 Falcon 门槛

> 日期：2026-10-12
> 基线：`2026-10-12-development-handoff.md`（v0.1）
> 范围：交接文档 P0 全部条目，P1 中除“主张级去重与冲突合并”外的全部条目

## 1. 解决了什么问题

v0.1 最近一次真实运行只采到 2 个来源，另有 3 个失败。失败原因统一记为 `source collection failed`，无法判断原因。复查发现，失败的 Wikimedia 链接正是 2025 年 7 月版 *ATP 3-20.15 Tank Platoon*，也是这次检索中最权威的来源。v0.2 的目标是让每个 URL 的去留都有据可查，优先找到并采用官方条令和学术来源，再用明确的门槛判断证据包能否交给 Falcon。

## 2. 主要变化

| 方面 | v0.1 | v0.2 |
| --- | --- | --- |
| 发现渠道 | Tavily `basic`，单一检索式列表 | 三个渠道：通用网页（Tavily，默认 `advanced`）、条令/官方域名（Tavily `include_domains`）、学术索引（OpenAlex） |
| 检索计划 | 研究问题 + 网页检索式 | 另增 `scholarly_queries`、`doctrine_queries`，自动去重并截断到 4 条 |
| PDF 判断 | 仅看 URL 是否以 `.pdf` 结尾 | 依据 `Content-Type` 和 `%PDF` 签名；`arxiv.org/abs` 自动改取 PDF |
| 下载 | PDF 与网页各有一套下载逻辑 | 统一的 `web/fetch.py`：重定向逐跳校验、仅重试 429/5xx/超时/断连、遵守 `Retry-After`、按类型限制大小 |
| 失败原因 | `source collection failed` | 分类记录：`http_error`（含状态码）、`dns_error`、`security_rejected`、`timeout`、`rate_limited`、`too_large`、`unsupported_content_type`、`invalid_pdf`、`no_extractable_text`、`blocked_domain`、`not_open_access`、`search_failed` |
| 候选记录 | 只有成功来源和失败 URL | `candidates` 台账：每个搜索结果的渠道、检索式、排名、预估质量、优先级、最终决策和原因 |
| 去重 | URL 精确匹配 | 规范化 URL → DOI → 内容 SHA-256（识别镜像） |
| 来源质量 | 无 | `evidence/quality.py` 确定性规则，A–D 四级，每一分都有文字依据，与 PaperQA 相关性分开保存 |
| 原始证据 | 只存提取后的 Markdown | 另存原始 HTML 和标准化 JSON（`raw/`） |
| PaperQA | 每个问题重建 `Docs` 并重新嵌入全部文档 | 每次运行只建一次语料库（`build_corpus`），各问题复用（`query_corpus`） |
| 解析失败 | 一个文档解析失败会终止整次运行 | 记入 `ingest_failures`，其余文档继续 |
| 证据溯源 | 只有引用字符串 | 每条证据带 `source_id` 及该来源的质量等级 |
| 可复现性 | 无运行记录 | `manifest`：模型、提示词版本、质量规则版本、依赖版本、Git 提交、各阶段耗时、检索参数（不含密钥） |
| 进入 Falcon | 无门槛 | `crow/readiness.py` 五项检查，报告首段给出结论 |
| 冒烟测试 | 手动运行 CLI | `tests/live/`，默认不运行，`pytest -m live` 显式触发 |

## 3. Falcon 输入门槛（`falcon-gate-2026.10.1`）

| 检查 | 默认门槛 |
| --- | --- |
| 可被 PaperQA 解析的来源 | ≥ 3 |
| A/B 级来源 | ≥ 2 |
| 研究问题覆盖率：至少 2 条相关性 ≥ 6/10 证据，且回答未声明资料不足 | ≥ 75% |
| 强证据中来自 A/B 级来源的比例 | ≥ 50% |
| 回答声明资料不足的问题占比（启发式识别） | ≤ 25% |

门槛参数在 `ReadinessThresholds` 中定义，可以按需调整。用这套规则回看 v0.1 最近一次运行，五项检查全部不通过（见 `tests/unit/crow/test_readiness.py`）。

## 4. 来源质量规则（`quality-rules-2026.10.1`）

基础分 0.30，按以下规则加减：

- 官方主机（`.mil`、`.gov`、`nato.int` 等）+0.40；学术主机或有 DOI +0.30；研究机构 +0.25；文档存档/镜像站 +0.10；新闻、行业媒体或百科 +0.05；
- 标题或路径含条令编号（FM、ATP、ADP、JP、AJP、STANAG、MCWP 等）+0.15；
- DOI +0.10，作者 +0.05，年份 +0.03，载体 +0.03，同行评审类型 +0.05（预印本 −0.05），被引 ≥ 10 次 +0.05（≥ 100 次 +0.08），PDF 全文 +0.03；
- 视频、社交、论坛和电商主机直接评为 D 级，在预筛阶段拒绝。

分级：A ≥ 0.75，B ≥ 0.55，C ≥ 0.35，其余为 D。

## 5. 新增配置（均有默认值，原 `.env` 不改也能运行）

```dotenv
TAVILY_SEARCH_DEPTH=advanced     # basic 消耗 1 credit；advanced 消耗 2 credits，召回更好
CROW_CONTACT_EMAIL=you@example.org   # 建议填写；Wikimedia 和 OpenAlex 要求客户端可识别
OPENALEX_API_KEY=                # OpenAlex 返回 401/403/429 时填写（免费申请）
OPENALEX_MIN_YEAR=
CROW_MAX_SOURCES=12
CROW_ENABLE_SCHOLARLY=true
CROW_ENABLE_DOCTRINE=true
CROW_DOCTRINE_DOMAINS=           # 逗号分隔；留空使用内置列表
CROW_HTTP_PROXY=                 # 例如 http://127.0.0.1:7890
CROW_ALLOWED_PROXY_CIDRS=        # 仅限 TUN/fake-IP 模式代理，例如 198.18.0.0/15
```

**代理说明。** v0.1 设置了 `trust_env=False`，会忽略 shell 中的 `HTTP(S)_PROXY`；v0.2 保留这一设计，改为通过 `CROW_HTTP_PROXY` 显式配置代理。如果代理工作在 TUN/fake-IP 模式，本机 DNS 会返回 `198.18.x.x` 地址，SSRF 防护会把它当作非公网地址拒绝，报告中显示为 `security_rejected`。这种情况下，只需把该网段加入 `CROW_ALLOWED_PROXY_CIDRS`。

## 7. 对比上一次运行时重点看什么

1. 附录 A 台账中的 Wikimedia ATP 3-20.15 链接：现在应为“采用”或“重复内容（镜像）”。如果仍失败，原因类别会指明是 `dns_error`、`security_rejected` 还是 `http_error 403`，对应处理方式见第 5 节。
2. `条令与官方文献检索式` 和 `scholarly` 渠道带来的 A/B 级来源数量。
3. 第 3.4 节人工补采清单：列出无法自动下载但可能有价值的来源。
4. 附录 B 阶段耗时：`embed_corpus` 应只出现一次。
